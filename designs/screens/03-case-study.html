As tenant organizations surged past 320+ enterprise accounts, our core billing and analytics dashboard experienced extreme latency degradation. Under peak morning ingestion cycles (40,000 requests/minute), unindexed nested queries triggered heavy sequential scans across multi-gigabyte audit logs.

03

Technical Decisions & Code Diffs

Rather than upgrading cloud database instances to absorb sloppy application code, we resolved the root inefficiencies in schema design and query execution planning.

DECISION 01

Eliminating N+1 Prisma ORM Joins via Native CTEs

SQL DTO Aggregation

Replacing multiple sequential nested ORM queries with a single Common Table Expression (CTE) utilizing json_agg reduced total database round-trips from 24 down to exactly 1 per request.

close BEFORE (Prisma In-Memory) 680ms Latency 
const orgs = await prisma.org.findMany({
  where: { status: 'ACTIVE' },
  include: {
    tenants: {
      include: {
        metrics: { take: 50 },
        invoices: { take: 10 }
      }
    }
  }
});
// 24 cascading roundtrips
// Loads 14,000 objects in RAM
check AFTER (Native CTE + JSON_AGG) 32ms Latency 
WITH aggregated_tenants AS (
  SELECT t.org_id, 
         json_agg(t.* ORDER BY t.created_at DESC) as payload
  FROM tenants t
  GROUP BY t.org_id
)
SELECT o.id, o.name, at.payload
FROM orgs o
JOIN aggregated_tenants at ON at.org_id = o.id
WHERE o.status = 'ACTIVE';
DECISION 02

Partial GIN & Composite B-Tree Index Hierarchy

PostgreSQL 16

Unindexed queries inside the raw event_payload JSONB field caused full sequence scans across 14,000,000+ rows. We created partial indexes targeted exclusively at active tenants.

// Zero-Downtime Migration Script
CREATE INDEX CONCURRENTLY idx_events_tenant_active
ON events (tenant_id, created_at DESC)
WHERE status = 'ACTIVE' AND deleted_at IS NULL;
// JSONB Partial Expression Index for Audit Queries:
CREATE INDEX CONCURRENTLY idx_events_jsonb_path_ops
ON events USING GIN ((payload->'action_type') jsonb_path_ops);
